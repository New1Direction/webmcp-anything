Title
Show HN: wmcp.sh – independent A-F trust grade for MCP servers + OAuth vault
Body / first comment
wmcp.sh is a trust layer and OAuth vault for MCP (Model Context Protocol) servers, running on Cloudflare Workers. Two things are the core of it: 1) An independent A–F trust grade for any MCP server. We score across spec conformance (20%), security mapped to the OWASP MCP Top 10 (30%), reliability (20%), tool hygiene (15%), and transparency (15%). Every host gets a grade page at https://wmcp.sh/mcp/grade/ and an embeddable SVG badge. The grade is free and is not for sale. We don't sell A's. The part we care about most: grades are continuously watched for drift. A server you trusted on Monday can change its tool surface on Friday (the CVE-2025-54136 class of rug-pull, where the description/behavior an agent reads shifts after you've granted trust). A one-shot static scanner structurally cannot catch that, because it never looks again. We re-check. 2) An OAuth vault that injects and refreshes tokens so agents never see a credential. You connect a provider once at https://wmcp.sh/connect, then any agent (Claude, Cursor, Codex) calls it at https://wmcp.sh/mcp/ and we inject the OAuth bearer token and auto-refresh it. Credentials are encrypted at rest and never passed in tool args. 7 providers are live: Linear, Notion, Atlassian (Jira+Confluence), Asana, PayPal, Sentry, DefiLlama. All onboard via RFC 7591 Dynamic Client Registration + PKCE, so there's zero per-app client setup. There's also an agent-callable trust oracle (itself an MCP server at https://wmcp.sh/mcp/trust) with tools grade_mcp_server, check_mcp_drift, and verify_before_execute, so an agent can gate a connection on the grade before it executes anything. If you'd rather hit REST: GET https://wmcp.sh/api/v1/mcp/verify?url=. Honest limitation: the v1 grade is built from static + spec signals gathered from a single connection to the server. It tells you what a server claims and how it's configured, not yet how it actually behaves under real traffic. The next step is behavioral annotation-truthing through the proxy: checking whether a tool's stated behavior matches what it actually does when called. That's not shipped yet. What I'd genuinely like: grade a server you depend on at https://wmcp.sh/mcp/grade/ and tell me where the grade is wrong, too generous, or too harsh. And try to break the verify oracle or the vault flow. The grade is only worth anything if it survives people poking at it. Positioning, plainly: Moody's for the long tail of MCP servers, with the vault as the part that pays for it. WebMCP adoption is near zero today, which is exactly why now is the time to set the trust signal.

2 · Why it's written this way

HN rewards substance and punishes marketing. Every choice in that body is deliberate:

It opens with the thing, not a greeting

First sentence states exactly what it is. No "Hi HN," no story windup — HN's algorithm and readers both drop those fast.

Two concrete mechanisms, with numbers

The grade weights (20/30/20/15/15) and the named primitives (RFC 7591 DCR, PKCE, the three oracle tools) signal "this person built the thing," which is the only credibility that matters here.

The differentiator is a verb HN understands: rug-pull

"A server you trusted Monday changes Friday" + the CVE reference frames continuous drift-watching as a real attack class a static scanner structurally can't catch — not a feature list.

It volunteers a limitation

The "v1 grade is static+spec, behavioral truthing isn't shipped" paragraph is the single most important trust move. HN looks for what you're hiding; naming it first disarms the top critical comment before it's written.

It ends with an ask, not a pitch

"Grade a server you depend on and tell me where I'm wrong / try to break it" invites participation. Comments = ranking. The "we don't sell A's" line pre-empts the obvious "isn't a paid grade a conflict of interest?" objection.

3 · How to land it — the playbook

Timing

  • Tue–Thu, 8:00–10:00am US Pacific. Best window for sustained US + EU-afternoon traffic. Avoid Fri/weekends (low) and Mon (backlog).
  • Post when you have 3 clear hours free after. The first 1–2h decide everything.

The first 2 hours (this is the whole game)

HN ranks on early comment velocity + upvote rate, not raw votes. A post that gets 5 thoughtful replies in 30 min beats one that gets 20 silent upvotes.
1
Post the body as the first comment immediately after submitting (the URL is the link; the body text goes in a comment). Some prefer text-post; for a live product, link-to-/connect + body-as-comment works well.
2
Reply to every top-level comment within minutes, especially critical ones. Speed of response is visible and rewarded.
3
Answer criticism with: acknowledge → what you'll do → move on. Never defensive, never argue. "Fair — that's exactly the v2 behavioral check; here's the gap today" wins the room.
4
Don't ask for upvotes anywhere. HN auto-penalizes vote solicitation and "it's on HN!" tweets that send a vote spike. Let it rank organically.

Prepared answers (have these ready to paste)

Likely commentYour move
"A paid grade is a conflict of interest."The grade is free, computed by one open rubric, identical whether you pay. Revenue is custody + monitoring, never the score. Point at the methodology section on any grade page.
"Isn't this just a security scanner? Snyk/etc. exist."Scanners read the manifest once. This is a runtime reputation signal that keeps watching for post-trust drift (rug-pulls) — the thing a one-shot scan structurally misses.
"How is the grade not gameable?"v1 is static+spec from a live connection (hard to fake protocol conformance + tool hygiene). Behavioral truthing through the proxy is next. Invite them to try to game a real grade and report it.
"Why trust YOU as the authority?"Don't ask for trust — the rubric is open and every grade is reproducible. Independence is the product; the moment it's for sale it's worthless, which is why it isn't.
"OAuth vault = single point of failure / you hold my tokens."True, name it. Encrypted at rest, never in tool args, per-provider, revocable. The alternative (tokens pasted into agent configs) is worse. Self-host is possible (MIT).

Force-multipliers

  • Have a live grade ready to link — e.g. grade a well-known MCP server beforehand so you can drop wmcp.sh/mcp/grade/<host> in replies. A clickable artifact > any description.
  • The registry listing is live (io.github.New1Direction/trust-oracle) — mention agents can add the oracle in one line. Concrete = credible.
  • Cross-post the X thread + r/mcp post a few hours later, but link to the comments discussion, not "upvote me." (Both drafts are in launch/.)
  • If it stalls, don't repost same-day. Wait a week, lead with a different angle (the X thread's drift hook, or a specific surprising grade you found).
One honest caveat to expect: someone will ask for a concrete example of a server whose grade changed. If you have one from the drift history, it's your strongest possible reply. If not, say the monitor is live and you're accumulating the dataset — don't fabricate one.
